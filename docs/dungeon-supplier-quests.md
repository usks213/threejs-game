# 補給所から受ける最初の依頼

2026-10-08。110項目台帳ECON-02の限定実装。遠征前に目標を受け、実際に帰還し、
回収した物を納めて次の補給へつなげる。全商人・討伐/製作クエスト・陣営評価の完成ではない。

## 遊ぶ流れ

1. 補給所で「初めての生還」を自分で受注する。
2. 実際の遠征から生きて帰る。帰還時に目標が達成されても報酬は自動受取にしない。
3. 補給所へ戻り20金貨の報酬を受け取ると、次の「補給所の鉱石」が開く。
4. その依頼を受注し、自分の倉庫にある帰還済みの鉱石を選んで合計2個納品する。
5. 納品で品物は減るが、金貨は別の報酬受取で30増える。余った数量は元のIDのまま保持する。
6. 再読込しても進捗と受取済み状態は残り、同じ報酬を再受取できない。

二件は一回ずつの教習用依頼で、毎遠征の金貨供給ではない。
既に帰還して倉庫に置いた鉱石も納品できる。未帰還の鞄、受取待ち、他人の品、
無料キット、鉱石以外の品を黙って消費しない。何を何個納めるかを画面に表示する。

## 保存と安全性

- 依頼日誌は既存の部屋・探索者保存に追加する本人専用の任意フィールド。旧保存の欠落は空扱い。
- ロビーで準備を解除している間だけ受注・納品・報酬受取できる。遠征中の書換を拒否。
- 帰還はサーバーの抽出処理だけが進捗へ記録し、クライアントから進捗値や報酬量を指定できない。
- 納品は実際の所有ID/種類/帰還済み属性/数量を確認し、必要な数だけを一括で消費する。
- 報酬は前提・達成・受取済み・金貨上限を確認して一回だけ加算し、理由を取引履歴へ残す。
- 再送・二重操作・別人のID・壊れた日誌を拒否。保存成功前の成功通知を出さず、失敗時に倉庫を初期化しない。
- 新しいアカウント、権限、保存binding、有料資源、既存データの削除や移行は追加しない。

## 受入条件

単体で前提と状態制限、実帰還以外の進捗拒否、必要数量の消費、余り保持、
未帰還品/対象違い、二重受取、上限、本人非公開、保存失敗と再接続、旧保存を確認する。

公開PC/Androidでは、通常UIで受注し、実際の箱を開けて鉱石を拾い、45秒後の出口へ帰還。
第一報酬→第二受注→実鉱石納品→第二報酬→再読込を行い、合計50金貨と所有物の一致、
受取済み表示を確認する。画面と品目記録を保存して検査する。
既存の全PvPvE・容量境界・補給・WebKitの受入条件も維持する。

対象SHAの公開CIで確認するまで、実ブラウザの完成とは扱わない。
