# 倉庫満杯時の帰還品を失わない受取待ち

2026-10-07。110項目台帳のINV-02にある「満杯時に報酬を消さず受取待ちにする」の限定実装。
アカウント共通倉庫、共有倉庫、追加ページ、容量販売ではない。

## プレイヤーの流れ

1. 通常どおり生きて脱出口で帰還を完了する。
2. 携行品は倉庫に入る分だけ保管し、残りは本人専用の「受取待ちの帰還品」へ残す。
3. 倉庫が満杯でも帰還を取り消さず、脱出口を一回だけ消費して生存結果を確定する。
4. 全員の遠征が終わったら補給所へ戻り、受取待ちの品を選んで倉庫または鞄へ受け取る。
5. 倉庫の売却や既存の持物移動で空きを作れる。目的地に空きがないと受取は成立しない。
6. 全品を受け取るまでは準備・次の遠征開始・補給購入を止める。売却と持物整理は続けられる。

受取待ちは一回の携行袋と同じ10×5の上限を持つ。一つの受取待ちを解消する前に
次の遠征へ出られず、購入でも増やせないため、無制限の追加倉庫にはしない。
鞄へ受け取れば、満杯の倉庫へ無理に詰め込まず次の遠征へ持ち出すこともできる。

## 保存と所有権

- 既存の部屋・探索者の保存内に任意のpendingReturn配列を追加。古い保存の欠落値は空扱い。
- 倉庫・鞄・受取待ち・箱・死体の間で同一item IDを重複所有させない。
- 受取待ちは帰還した品だけで、数量・形・品質・IDを保持する。購入や無料品の売却条件は維持。
- 受取待ちのsnapshotは本人だけへ送る。他人のbatchを指定する操作は受け付けない。
- 受取はサーバーの既存直列キューで確定し、保存成功後だけ通知する。満杯・再送・対象違いは安全に拒否。
- 壊れたbatch、重複ID、容量超過は保存全体を拒否し、元の倉庫を空にして初期化しない。
- 新しいstorage binding、課金、認証、アカウント共通データは追加しない。

## 受入

単体では完全満杯・断片化・一部だけ入る場合の帰還、ID/個数保存、受取拒否の原子性、
再送、他人からの非公開、保存失敗、再接続、古い保存との互換性を検査する。

公開ブラウザ試験は新しい部屋で通常の遠征・無料キット・箱取得・45秒後の帰還を反復し、
実際に倉庫を満杯にしてから受取待ちを作る。生成用の公開デバッグ機能や状態注入は使わない。
PCとAndroid相当の別ジョブで、帰還成功、再読込保持、受取先の満杯表示、実タップ/クリック受取、
整理後の準備解除を確認する。新しい長期反復試験は既存の全PvPvEとは独立させ、
従来の四体AI・対人・死体loot・240秒以内の生存抽出の条件は変えない。

実装中の受入定義であり、公開先の対象SHAとCI結果を確認するまでブラウザ成功を意味しない。
