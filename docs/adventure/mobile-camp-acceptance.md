# 移動拠点・移動倉庫: ローカル実装と受入記録

対象: ITEM-04 / QUEST-05。静的な箱を車両の横へ置く代替ではなく、既存の権威物理・接着グラフに収納と寝床を加える。公開ブラウザ受入と実機操作は別工程で、以下のローカル試験だけで全仕様完成とはしない。

## 実装

- `storage`（収納箱）と `bed`（寝床）は既存の部品と同じ位置・Quaternion・角速度・接触処理を使用する。1ルーム64部品、1構造物16部品の予算を共有し、制作コストは収納4、寝床3。設置の重なり検査と部品予算検査を素材消費より先に行う。
- 収納は8スタック・8品種・合計400個・積載重量80まで。素材、食料、消耗品を扱い、個人ごとの品質・耐久を持つ装備は対象外。実重量は既存の品物重量を使い、全体の重心・慣性・推力への応答に加算する。荷物を増やしても船体の浮力は増加しない。
- 作成者専用が初期状態。作成者が共有を許可した収納だけ仲間が閲覧・出し入れできる。権威側は双方の個数、容量、所持枠・重量、距離、遮蔽物、操作競合を先に検査し、一つの同期処理で個人所持品と収納を更新する。
- 出し入れと共有変更で構造物のepochを更新する。公開通信では対象epoch必須。既存の操作ID重複除外・永続化前ACK禁止により、再送や保存後ACK欠損で再度移さない。
- 物体の軌跡には収納を含めない。設計帳から再建しても収納品・充電・寝床登録を複製しない。
- 積荷のある収納は解体できない。環境によって壊れた場合は元のID・所有権・内容を持つ一つの残骸へ分離し、出庫だけを許可する。最後の品物を回収した後に残骸を除去する。重量0の硬貨も内容ありとして保護する。
- 私物の収納・寝床を含む構造物は他人が運転・運搬できない。別の作成者の構造物へ追加する拠点部品は先に共有し、接着中は私物へ戻せない。これにより、私物の家具を接着して他人の車両を操作不能にする行為を防ぐ。

## 寝床の安全条件

`sky-camp` は板・使用可能な収納・寝床が同じ接着グラフにある場合だけ登録する。登録は体力を回復せず、時間を進めず、持ち物を増やさない。

復活地点は保存された座標ではなく、復活する瞬間の寝床IDと現在の姿勢から計算する。

- 地上で接地し、動力を止めている
- 水平速度0.2m/s以下・角速度0.1rad/s以下。接地ソルバーの上下振動は0.5m/s以下まで許容するが、船体底面4点の接地確認が別に必須
- 寝床が十分に水平で、燃焼・凍結・破損がない
- 操作lease・牽引・軌跡再生・搭乗中ではない
- 敵、火、水、対策のない暑さ/寒さ、他のプレイヤー、保護された入口から離れている
- 正確なOBB対カプセル判定で部品と重ならず、0.1m間隔の密な静的空間検査を通る

安全条件を失った寝床は使わず、現在も安全な通常の復活位置、または開始地点へ戻る。通常の保存座標も地形変更・占有・水・障害物を再検査する。移動する編集禁止領域は作らない。

## 保存と可視性

- 収納は `SkyboundSave.storage`、個人の寝床参照は `SkyboundSave.camps` に保存する。過去のversion1/2保存・Generator1〜3のデータを保持する。
- 部品の公開状態は荷重だけを含む。収納品は作成者または明示的な共有先への専用snapshotにだけ含める。他人の個人所持品は含めない。
- portable exportは本人所有の収納と本人の寝床参照だけを引き継ぐ。他人の非公開内容を削り、削除後の荷重を再計算する。本人の所有者IDだけhostへ対応付ける。
- 物体レプリカは公開荷重を受け取れるが、以前のローカル収納/寝床記録を残さない。ゲストのレプリカで共有正本を上書きしない既存方針を維持する。
- 13種類の部品を旧クライアントが誤解しないよう通信protocolを5へ更新する。保存形式versionは2の互換拡張。

## 残る受入と制限

- 装備の収納/受渡しは、個体ごとの耐久・品質・合成を保持する方式が整うまで未実装。
- 浮いている船・飛行中の構造物からの復活は対象外。陸上に停車して使う。
- 寝床は復活先の登録。睡眠アニメーションや時間早送り、休息回復は含まない。
- 公開2ブラウザ、スマートフォンでの収納/接着/寝床の実操作、画面の可読性、長時間運転と環境破壊を含む公開受入は未完了。
- この区切りの実装と試験はローカルのみ。公開URL、外部デプロイ、Git push、mainマージはこの記録の成功条件に含めていない。
