# 立ち乗りの停止不具合と、水上運搬の追加受入

2026-10-05 UTC。元の2人着席車両の証拠は `vehicle-input-acceptance.md` に保持する。本書は別ソースの追加検証であり、以前のreceiptを書き換えない。

## 実操作で発見した停止不具合

通常の制作操作で作った車両を保存し、Bが空いている席の上へ歩行・ジャンプで登った。Bには搭乗権を付けず、Aだけが操縦席に座った。この状態でAが前進すると、電力は25.2から17.47へ減るのに車両は停止した。

原因は、わずかに傾いた支持面と、直立capsuleの丸い足元の不一致だった。以前の床判定は足元を平面の高さへ置く。精密なOBB対capsule判定では、丸い足元がその支持面へわずかに入り込み、`passengersClear` が現在位置そのものも拒否していた。水平な部品を直接配置した単体fixtureでは検出できなかった。

- 失敗した実操作checkpointのSHA-256: `390cb2bcd4a018428379b9aea6e04d3a0253c99aef8d1bb0dbe749740ab8918e`
- 失敗時ゲームsource hash: `31edb61b7f99abbfb51f08f1f2f38302f9a86b99963cc83e09a4be8067504a5f`
- 新回帰試験の修正前結果: 4件中3件失敗。成功扱いにしない。

## 修正と保護

`src/game/skybound/platform.ts` と `character.ts` で同じcapsule支持高さを使い、傾いた面の法線Yに応じた `radius * (1 / normalY - 1)` を加えた。床のpitch/rollが変わる時も直立capsuleの支持高さを再計算する。

支持部品との精密な衝突判定自体を無効にしていない。別部品、壁、天井、他プレイヤー、境界の拒否を維持する。深く埋まった人やジャンプ中の人を立ち乗り扱いにしない。`tests/unit/tilted-deck-support.test.ts` は実際の失敗poseを最小限の数値として保持し、上記の条件を確認する。

関連79試験/14ファイル、アプリ/Signaling/Coop型検査、production buildに合格。全単体試験の最終統合は別CIへ委ね、ここでは全件合格とは表記しない。

## 新規世界からの実2WebSocket合格

2026-10-05 12:55:27–12:57:09 UTC。上記3区間を空の世界から実行し、61操作すべてのACK、1,625tick、11段階保存、3回のサーバープロセス再起動、切断/再参加各1回を通した。4サーバー世代すべてで修正後source hashが一致した。

正本と各クライアントの完全snapshot比較1,090件、水比較1,090件が一致。失敗・未照合は0件。追加のread-only検証で、11段階すべての部品・接着・姿勢・電力・地形編集・全保存水・個人位置と持ち物/装備/進行が一致した。

追加検証では、個人セーブの秒数だけに表現差があった。直接Sessionをstepした直後の個人時計は、`stepPersonal`で共有時計から1tick進む。ネットワークsnapshotを読む`withActor`は個人時計を共有時計へそろえる。共有世界の時計は全段階で厳密一致し、22個人比較中10件だけが1/30秒違った。例えば最初の島ではsource個人28.433333333333906秒、socket個人/共有28.40000000000057秒。

`verify-vehicle-journey-replay.ts` は無条件に秒数を除外しない。両時計が共有時計そのものか、ちょうど1/30秒先であることを1e-9の数値許容で確認してから、その1フィールドだけを共有時計へ正規化する。生のsource/socket/共有秒数を`clockNormalizations`へ残し、他の個人フィールドはすべて厳密比較する。

ローカルreceiptは `/tmp/voxel-vehicle-deck-water-socket-01/summary.json` と `vehicle-journey-verification.json`。結合経緯は `/tmp/voxel-vehicle-deck-water-composed-01/provenance.json`。一時ファイルは公開済みGit artifactではなく、再実行経路と結果を本書に記録する。追加3scriptのstrict TypeScript検査も合格した。

## 失敗した狭い船体も保持

最初の水上試行は、車輪だけを外して充電済み電池を残した狭い構造物だった。実放水後に転覆し、水上運搬の条件を満たせなかった。両者の体力25、搭乗権の解除、木製4部品の保持を失敗traceと行動観測から確認した。収納部品と積荷はなく、積荷保全の試験ではない。

この試行は「水上運搬合格」へ数えない。ソケット未実施のSession層における、転覆・安全退避の観測として残す。

## 再現用scriptと残り

- `scripts/vehicle-deck-water-acceptance.ts`: 獲得済み車両からの立ち乗り。`VEHICLE_RESUME` と `VEHICLE_OUTPUT` を指定する。
- `scripts/vehicle-water-acceptance.ts`: 獲得済み立ち乗りcheckpointから、解体・追加板・採掘・放水・2人水上運搬。
- `scripts/verify-vehicle-journey-replay.ts`: 結合traceの各source checkpointと実ソケット自身のcheckpointについて、車両、地形編集、全保存水、個人の位置・持ち物・進行を照合する。

水上検査は小さな人工の池での短い運搬であり、外海や長距離航海ではない。荷重を変えた比較、公開ブラウザの描画/入力、実機FPS、実時間30Hz、Workers128MB内運用は別の受入として残る。
