# 水の通信辞書の再利用

2026-10-05。水snapshotのvisitor案は厳密一致したが、平均の改善が小さい/再現しなかったため採用していない。通常のsnapshot APIと権威roomは維持し、`FluidWireEncoder`だけを追加で変更する。

毎回8192件のMapを再構築する代わりに辞書を保持し、検証中は訪問印だけを更新する。すべての入力に成功した後で値・削除・revisionをまとめて確定する。前回の表示順を別配列に残し、削除IDの順序も従来と完全に同じにする。不正/重複/過大入力や途中の例外では、前回の値と通信revisionを変えない。訪問印の安全整数上限も処理する。

同じ実保存の水snapshot配列で、旧新を交互順に360回比較。全deltaのJSONが毎回一致した。純encoder時間は平均1.818→1.232ms、p95 3.077→2.447ms。冷たいサンプルも除外していない。

4人・成熟保存・300tickのbundleプロファイルはroom.step平均37.30ms、p95 82.26ms。第2回固定版の平均40.15msから改善したが、短い別実行の差にはCPU/GC変動も含むため、改善率の主な根拠は上記の交互順比較。33.3msの品質目標は未達。公開30HzやWorkersメモリの達成として扱わない。

完全decoded snapshot比較8回に合格し、ゲーム保存全体は従来と同じ `d298b62a6e39b247a87a6ff4874a3cf09e45418f67a934c2cbece59b3b0f6a3d`。保持heapはNodeで約55.71MBとなり、前回約53.15MBから増加。辞書entryの訪問情報と前回順序を保持する代わりに毎frameのMap割当を減らす変更で、保持メモリ削減とはしていない。

関連16試験とTypeScript検査に合格。新しい試験は表示順の変更、値を仮計算した後の不正値、未登録IDの重複、空表示、訪問印上限からの復帰を検証する。従来の差分上限/原子的拒否/compact binary/compound decoderの確認も維持した。
