# ボクセル協力冒険・新仕様 v0.1

作成: 2026-10-04。参考分類は `totk-reference-checklist.md`。以下は新作の独自設計であり、参考作品の内部仕様ではない。名称は仮称。全チェックは初期状態では未実装・未検証。コードの実測に合わせ、変更理由を残して改訂する。

## 0. 目標とスコープの正直な扱い

プレイヤーが見つけた地形に対し「掘る、積む、登る、飛ぶ、組み立てる、仲間と運ぶ」の選択肢で答えを作る、三層ボクセル協力アクション冒険。世界・敵・キャラクター・物語・音楽・モデル・アイコンは独自制作。参考作品の地図や固有アセット、台詞、クエストを再現しない。

依頼の終点は全仕様の実装と公開検証。最初のネットワーク実証や縦切り版は中間成果であり、全仕様完成ではない。実装台帳に全IDを残し、各項目を「未着手 / 実装中 / ローカル合格 / 公開合格 / ブロック」で管理する。「予定」と「遊べる」は分ける。

## 1. 開発順序とゲート

1. **M0 実マルチ成立**: 独立した2クライアントが同じルームで移動、同じ物体を操作、切断から復帰。実サーバーまたは実接続経路を使用し、同期のダミーは禁止。
2. **M1 共有ボクセル世界**: 同じ地形・編集結果・持ち物・時刻・敵を観測。新規参加と復帰で同一状態。
3. **M2 冒険の骨格**: 三層を行き来し、集め、作り、戦い、謎を解き、保存して再開。
4. **M3 能力と物理の相互作用**: 物体編集、合成、履歴、上昇、装置、属性を協力に適合。
5. **M4 完全バックログと品質**: コンテンツ拡張、UI、音、アクセシビリティ、負荷、荒らし対策。
6. **M5 公開検証**: 新作専用URL、別端末接続、最終commitのCI、既存版への非干渉を確認。

M0が通るまで見た目や戦闘の拡張をネットワーク成立の代わりにしない。

## 2. NET: ネットワークと権威

### NET-01 接続方式
- 初期合格人数は2名。製品目標4名協力は別負荷試験が通った場合に表記する。
- 既存リポジトリの利用可能なサーバー/シグナリング/公開環境を先に監査し、その制約内で実装。サービス契約や新しい鍵を勝手に導入しない。
- 推奨はルーム単位の権威シミュレーション。クライアントは操作意図を送り、位置や所持数の最終決定権を持たない。
- ホスト権威でしか動かない場合は明記し、ホスト離脱からの再開を実装。ピア間の同一浮動小数点結果を前提にしない。
- 公開静的ページだけで共有永続サーバーが存在するとはみなさない。ネット未接続はUIで明確に区別。

### NET-02 プロトコル
- handshakeにprotocolVersion、buildId、roomId、playerId/session、worldSeed、worldVersion、serverTick。
- 入力にsequence、clientTick、方向/ボタン、対象ID、commandId。重複コマンドの効果は一度だけ。
- スナップショットは権威tick・最後に受理した入力・エンティティrevision。欠損後は差分前提を破棄しフル再同期。
- ローカル操作の予測は許すが、権威結果で補正。遠隔キャラは補間。UIは接続中/同期中/接続済み/切断を示す。

### NET-03 共有編集・競合
- ボクセル編集はchunk座標、voxel座標、期待revision、材料消費を単一transactionにする。
- 同じ拾得物は権威側で一人にだけ移転。二人の同時拾得は片方成功、他方は「取得済み」。増殖しない。
- 物体移動/接着/逆再生は短命lease。所有者・期限を表示。競合は順番待ちではなく即座に拒否理由を返す。
- 操作中に切断したleaseは失効。接着体の子を別クライアントが同時に保持しない。

### NET-04 再接続・復旧
- 接続断中の破壊/取得/戦闘を無制限にローカル確定させない。
- 一時切断: 同一セッションの復帰、最後の確定位置/体力/在庫と世界revisionを取得。
- 再読み込み: 初回spawnと復帰spawnを区別。古いclient snapshotで世界を巻き戻さない。
- サーバー/ホスト再起動: 保存されたcheckpoint＋整合したイベント列から復元。保存なしの場合は明確に初期化表示。
- 新規参加は既存プレイヤー、設置物、破壊地形、敵、クエスト、時刻を受領後に操作可能。

### NET-05 安全性
- 不正座標、NaN、巨大payload、遠距離interaction、速度超過、負の在庫、古いrevision、過大command rateを拒否。
- ルーム分離、推測困難な招待ID、最大人数/物体/編集rate。tokenをURLやログに露出しない。
- 協力初期設定は味方ダメージなし。spawn/復帰地点と重要クエスト物体を破壊・封鎖できない。
- 他者の装備合成や建築の解体は所有権/共同設定に従う。復旧用履歴と自分の直近編集取消を用意。

## 3. WORLD: 全体が一貫したボクセル世界

- **WORLD-01** 地表「風原」、空「漂う台地」、地下「灯の洞海」。独自seed・地形・ランドマーク。地表から空/地下へ少なくとも一つの連続ルート。
- **WORLD-02** 地形密度/材質が描画・衝突・採掘・保存・同期の共通source。見た目だけ低polyで衝突が別平面という状態を許さない。
- **WORLD-03** チャンク読み込み、隣接境界、LOD、編集差分。未読込領域へ落下しない安全な待機/転送。
- **WORLD-04** 草原/森林/岩地/水辺/寒冷/高温の環境。遠くの目標を識別できるシルエット。
- **WORLD-05** 昼夜・天候・風はルーム共有。状態は権威seed/時刻で決定。ゲームに効く風と視覚的な揺れを区別。
- **WORLD-06** 水、浮力、洞窟、光源、採鉱。全水セルの高負荷流体は最初から要求しないが、簡易モデルの制限を仕様として表示。
- **WORLD-07** 採掘/積み上げで解決できる課題と保護領域。重要な進行ルートを破壊しても回復策がある。

## 4. MOVE: 操作・アクション

- **MOVE-01** 歩行、走行、ジャンプ、空中制御、坂/段差、着地、しゃがみ、回避。キーボード/マウス、対応端末の入力方式を明記。
- **MOVE-02** スタミナ付き登攀、掴まり、滑落。材質/濡れで条件変化。通信遅延で壁抜けしない。
- **MOVE-03** 滑空、急降下、上昇風。滑空は落下救済ではなく移動ルートの選択。
- **MOVE-04** 水泳、浮遊、岸上がり、溺れ前の予告。水面位置は双方一致。
- **MOVE-05** 荷台/乗り物への搭乗。床速度を加味し、遠隔からも足元が滑り続けない。
- **MOVE-06** 騎乗/牽引の独自生物。捕獲、呼び寄せ、追従、安全退避。M4コンテンツとして未実装なら残す。
- **MOVE-07** 戦闘/建築/照準カメラ。壁でカメラが遮蔽されたとき補正。感度・反転・視野角・揺れ軽減。

## 5. POWER/PHYS: 能力と創作物理

- **POWER-01「組み手」**: 対象をハイライト→lease取得→持ち上げ/回転→グリッド/接着点プレビュー→確定。木/石/金属に質量差。掴めない理由を表示。
- **POWER-02「継ぎ装」**: 独自素材を武器/盾/弾へ合成。完成効果、耐久、消費、解除結果を事前表示。合成/消費は権威transaction。
- **POWER-03「軌跡戻し」**: 物体だけの有限履歴を逆再生。世界時間、プレイヤー在庫、クエストを巻き戻さない。対象のleaseと履歴epochを固定し、接着変更で不整合な履歴は無効化。
- **POWER-04「天抜け」**: 真上の出口を探索して足場・頭上空間・保護領域を検証。プレビュー→確定。出口が塞がれたら取消。人や乗り物に埋まらない。
- **POWER-05「設計帳」**: 接着グラフの保存/再建。必要資材を原子的に消費し、設置領域と部品数を検査。任意コードや外部URLを読み込まない。
- **PHYS-01** 重力、衝突、質量、摩擦、浮力、押す/運ぶ/投げる。動的物体と静的ボクセルの境界一貫性。
- **PHYS-02** 板/梁/車輪/推進器/帆/電池/スイッチ/灯具/放射器。接着体の単一所有権と権威シミュレーション。動力残量の同期。
- **PHYS-03** 燃える木、濡れによる消火、冷却/凍結、導電、風、爆発の組合せ。ルール表・優先順・最大連鎖数を明示。
- **PHYS-04** 暫定予算: 1ルーム64 active rigid bodies、1構造物16部品、逆再生対象1人1個、履歴4秒、権威tick20Hzを出発点とする。これは未実測の提案値。既存方式を監査し、負荷試験で変更する。無制限を約束しない。
- **PHYS-05** 遠隔域sleep、権威の接触イベントから音/粒子を一度再生。過負荷時は新規生成を拒否し、既存世界を黙って破壊しない。

## 6. ITEM/COMBAT: 生存と戦闘

- **ITEM-01** 素材採集、採鉱、食材、通貨、ドロップ。所有権とstack上限。
- **ITEM-02** 料理/薬の独自レシピ。回復/耐寒/耐熱/スタミナ/発光。効果の重複上限と残時間。
- **ITEM-03** 武器/盾/防具、耐久予告、破損、修理/更新、装備強化、持ち物拡張。強化前後の数値比較。
- **ITEM-04** 交易、倉庫、受渡し、設計図管理。転送中の切断で二重取得・消失しない。
- **COMBAT-01** 近接/射撃/溜め/盾/回避/パリィ。ヒット・無敵・消費は権威側。遅延補償の上限を定める。
- **COMBAT-02** 全世界slow motionを避け、個人の照準補助/短い判定猶予として再設計。演出だけのスローなら入力同期と混同しない。
- **COMBAT-03** 独自の接近敵、射撃敵、飛行敵、防御敵、群れ、環境反応敵。索敵→追跡→予兆→攻撃→復帰、地形変更後の再経路。
- **COMBAT-04** 大型敵は弱点/部位/移動能力/装置の複数攻略法。攻撃予兆が二人に同じ時点で見える。
- **COMBAT-05** 協力蘇生、復帰地点、討伐報酬配分、途中参加。味方切断で進行不能にしない。

## 7. QUEST: 冒険・謎解き・進行

- **QUEST-01** 操作を実地で学ぶ導入島。移動、採掘、共有拾得、組み立て、協力復帰を順に体験。
- **QUEST-02** 小型試練: 重量スイッチ、運搬、風、電路、熱、逆再生、垂直通過。各試練に正攻法以外の解を許す。
- **QUEST-03** 地域ごとの大規模探索拠点と大型敵。独自物語、NPC、短い会話、サブ依頼、輸送/救助/復旧。
- **QUEST-04** 世界共通の設備状態と個人の発見/報酬を分離。二人同時完了は一度だけ記録。
- **QUEST-05** 体力/スタミナ/エネルギー/所持枠の成長、地図解放、移動拠点。新規参加者を永久に取り残さない追いつき導線。
- **QUEST-06** 発見図鑑、収集、地図ピン、道の記録、任意写真、ミニゲーム、拠点装飾。公開共有は自動で行わない。
- **QUEST-07** 最終目標、達成表示、クリア後の世界、周回/新規世界、進行リセットの明示確認。

## 8. UX/AV/SAVE: 仕上げ

- **UX-01** 体力・スタミナ・エネルギー・装備・仲間・接続状態・操作ガイド。入力装置に応じた表記。
- **UX-02** 地図の層切替、個人/共有ピン、目標ログ、検索/並替え、レシピ/設計帳、結果の通知。
- **UX-03** リマップ、字幕、文字倍率、色に依存しない重要表示、揺れ軽減、音量分離、長押し補助、迷子からの安全復帰。
- **AV-01** 全体を独自ボクセル造形に統一。顔・手足・道具の読みやすいシルエット。既存の滑らかな水/粒子は意図的な表現として明示。
- **AV-02** 三層ごとの色・霧・光・遠景。昼夜、風の草木、雲、天候、着地/打撃/素材音。参考作品の音源や楽曲は使用しない。
- **AV-03** 対象物の輪郭/置ける範囲/接着点/危険範囲。共有操作の所有者を見せる。
- **SAVE-01** 新作専用namespace。既存PR3のセーブを上書きしない。migration前backup、version識別、破損検出、export/import。
- **SAVE-02** 世界seed、voxel差分、構造物、在庫、進行、時間を整合したcheckpointで保存。保存時revisionを表示。
- **SAVE-03** ローカル保存と共有永続保存を区別し、ホストを閉じた際の挙動を明記。全員切断→再接続テスト。

- [ ] NET-A02 Aが箱を移動、Bも同結果。A/B同時操作は一方が拒否され、永久lockなし。
- [ ] NET-A03 同一素材の同時拾得: 総数が一度だけ移転。再送でも増えない。
- [ ] NET-A04 Aが地形を編集、Bの見た目と衝突が更新。B再入室でも同結果。

## 10. 記録形式

各IDに status、code paths、test names、tested build、evidence、remaining を持たせる。未着手を削除しない。試験不能と失敗を混同しない。実装を削る場合は理由を記録し、依頼全体の未完了として残す。現段階でこの文書は設計完了のみを示す。
