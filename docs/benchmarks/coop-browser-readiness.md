# 協力プレイの入力・開始地点・ブラウザ受入修正（2026-10-05）

## 確認した不具合

Actions [37283595515](https://github.com/usks213/threejs-game/actions/runs/37283595515) の公開2ブラウザ検証で、参加者は接続済みでも操作開始前に敵の攻撃を受けていた。公開版のトレースでは2人目のHPが25→7→5となり、Dキー押下後に0となった。描画・RAF間隔は最大約7.4秒で、入力送信も描画待ちになっていた。

ローカルサーバーの2ブラウザ検証では移動が成功した後、2人目のX座標が1.6から5.0まで進み、開始地点の木材が3mの拾得範囲外となった。また再試行時はPlaywrightの自動トレースと手動トレースが競合していた。

## 変更

- 移動キーの押下・解放時に直ちに入力を送信する。100msの入力更新を描画とは別に行い、保持中の操作をサーバーの無入力タイムアウト前に更新する。ジャンプも押下時に送信する。
- メニュー、フォーカス変更、非表示、blur、回転時は移動入力を解除する。読み込み中は見えない移動を送らない。協力接続でも送信入力を診断値へ記録する。
- Generator4の地表開始地点（X=0、Z=8）から半径6m、生成地表の高さ−2m〜+4mを普通の敵の対象選択・侵入から除く。過去の保存で中にいる敵は外へ退避できる。一般的な無敵、世界の一時停止、地底・空・任意の拠点の安全化は追加していない。発射済みの飛び道具や環境ダメージの一般規則も変えていない。
- 共有物資の同時回収を移動より先に検証する。移動では観察側が受信した正本座標を見てキーを解放し、操作側の座標、向き、ジャンプも従来どおり確認する。
- 2ブラウザのトレースをテスト側で一元管理し、失敗した試行ごとに保存する。失敗時にはHP・スタミナも記録する。

## ローカル確認

- TypeScript: 成功
- キー入力・共有物資・開始地点・敵の挙動: 15件成功
- 実際のSessionAuthorityと生成済みワールドで60秒間待ち、両参加者のHP25、木材12個の回収、入力による移動を確認
- 同じセッションで1人が開始地点の外へ歩くと既存の敵からダメージを受け、開始地点に残る人はHP25を維持
- 既存の遠距離射撃・近接・突進・盾・上下移動・旧Generatorの敵の回帰検証: 成功
- Vite本番ビルド: 成功

修正版の実ブラウザ受入・公開先照合は別途CIで確認する。ローカル環境のChromium起動制約のため、この記録をブラウザ受入成功として扱わない。

## 次の公開版3645d252での切り分けと局所IPC修正

Actions [37286376285](https://github.com/usks213/threejs-game/actions/runs/37286376285) では、ローカル共有サーバーの実ブラウザ2人の同時回収・移動が成功し、両方のHP25を維持した。地形編集は開始地点付近を狙ったため、正本の保護範囲チェックが拒否した。受入テストは東へ歩いてから掘るよう修正した。保護ルールや編集・両クライアント収束の検証は維持する。

公開先の2ブラウザは通信中・HP25でも地形の準備待ちで失敗した。最後の記録はepoch2、受信37/転送37、GPU転送合計43ms、メインの転送待ち0、Worker paused=false、nearReady=false、地形待ち1383。この証拠だけでは停止原因を確定できない。

実際の参加者セーブから測定すると、約7800セルを含む完全スナップショットが約0.8MBあり、入力ごとに全体をWorkerから返送していた。次の局所変更でこの重複を除いた。

- メイン→Workerの完全状態は処理中1件＋最新待機1件に制限。公開差分は従来どおり検証・展開し、完全な編集履歴と最新状態を保持する。
- Worker→メインは正本を適用した応答と予測移動をプレイヤー座標・tick・要求IDだけにする。メインが元の完全状態へ座標を合わせる。水や建築の正本データを省略した表示世界にはしない。
- epoch・要求ID・入力sequenceで古い予測を拒否。同一tickの状態変化、再接続時のack巻き戻り、旧epochの遅延応答を回帰検証する。
- Workerの診断へ処理中地形ID/経過時間、最終完了からの時間、転送クレジット数、状態適用時間を追加した。
- Desktopのカメラ回転は、ネイティブmousemoveの移動量・Pointer Lock・isTrustedを読取専用で記録し、実際の5段階マウス移動で検証する。カメラの製品コードは変更していない。

測定: 7819セルの完全応答をJSON化すると817,025 bytes、同じ入力の軽量応答は155 bytes（99.981%減）。これはローカルIPCに渡す実オブジェクトのJSON表現の大きさであり、ブラウザ内部の転送帯域を直接計測した値ではない。反復スナップショットを処理する実Workerハンドラーの回帰試験では、42個の近傍地形の準備と移動入力が成立し、対応する応答のJSON合計は141,280,450→26,577 bytesだった。

TypeScript、関連30件と追加した同一tick/再接続の2件、Playwrightのテスト検出、差分チェックは成功。修正後の公開2ブラウザの準備時間、編集・再接続、DesktopのPointer Lock回転は次の実ブラウザCIで確認する。IPC負荷を減らしたことを、公開先の停止原因の解消確認とは扱わない。
