# G2: 通常入力だけの2人遠征ルート

基準: 2026-10-06、PR4新ダンジョン、最初の遠征（raid 1 / seed 7919）。
実装: `tests/unit/dungeon-raid-journey.test.ts`。

これはサーバー受入試験の合格記録。独立ブラウザ、実TCP/WebSocket、公開Worker、タッチ操作の合格記録ではない。次のブラウザ受入へ転用するための具体的な経路である。

## 試験の境界

- 独立した2つの接続・参加キーで `DungeonServer.receive()` に通常の hello / input / action JSON を送る。
- 2人とも「灯守」keeper、初期HP110。ゲームが通常支給する片剣、盾、薬2回、術5回を使う。
- `now` を50msずつ進め、毎回 `DungeonServer.tick()` を呼ぶ。生存者は20Hzで入力を更新する。サーバー内の通常 `step()` だけが進行する。
- 位置、HP、敵、鞄、地形、経過時間、戦利品を直接書き換えない。初期敵4体を除去しない。試験専用の操作/APIは使わない。
- 判断のための状態読取は使う。入力・行動の連番、サーバーの送信頻度制限、移動衝突、戦闘後隙、敵の索敵・追跡・攻撃を通常どおり通す。
- 全checkpointを検証してJSON化。最後に保存JSONから新しいサーバーを構築し、同じ2つのキーで再参加する。
- ローカル実測は約0.5秒CPU側試験時間。10秒の試験上限を維持。遠征は54.50秒 / 1,090 tickで終了し、240秒未満という経路上限も検査する。

## 移動と戦闘の入力

座標は `(x,z)`。yaw 0 は北（-z）、正のxが東。移動は目的地に対して
`yaw = atan2(-(target.x-player.x), -(target.z-player.z))`、前進 `z=1`、横移動 `x=0`、pitch 0。目標まで0.2m未満で停止する。障害物の回り込みには通常の軸別衝突による滑りを使う。

移動中、6m以内で壁越しでない生きた敵が見えたら、最初に見つけた敵へ向き直って戦う。各tickで敵の現在位置へ同じyaw式で照準を更新する。

- 敵との距離が1.35mを超える間は前進、1.35m以下なら停止。
- 防御入力を保持する。サーバーは idle 中だけ盾を上げ、攻撃・回復・術中は盾を下げる修正後のルールを使用。防御しながら無傷で攻撃する抜け道には依存しない。
- 自分が idle、距離1.65m未満、敵が idle または recover のときだけ重攻撃を1回送る。連打で後隙を飛ばさない。
- 撃破後、HPが80未満なら自分の動作終了を待って薬を使用。薬を使い切った場合は灯守の術を使用。その後1.25秒静止する。近くの別の敵は止まらない。
- 全戦闘でプレイヤーが実際に被弾し、敵が通常攻撃で死亡したことを確認する。

PCへの対応: WASD移動、マウス/矢印視点、R重攻撃、Tまたは左クリック通常攻撃、Zまたは右クリック防御、Q回復、G術、E対象操作。箱・死体を開いた後は通常の戦利品UIから品物を選ぶ。ブラウザ試験では描画フレームとサーバーtickを同一視せず、状態・表示の到達を待つ。

## 経路

1. 先に参加したAが南西 `(-11,11)`、後に参加したBが北東 `(11,-11)` に出現。2人とも灯守を選び準備完了にして、Aが開始する。
2. Aは `(-12,7)` のchest0へ移動し、操作後1.6秒静止。開いた箱の鍵1個だけを拾う。
3. Aは `(-4,11)` → `(0,7.5)`。途中で南の番兵e3を倒し、薬1回を使用する。南扉の手前で待つ。
4. Bは `(0,-11)` → `(0,-7)`。途中で北の大剣番兵e2を倒し、薬1回を使用する。北扉の手前で待つ。
5. Aは `door-south` を開け、`(0,2)` へ移動。中央のe0、e1を通常戦闘で倒す。Aは残った薬1回と術1回を使う。
6. Bは `door-north` を開け、`(0,-2)` へ移動する。ここで初期敵4体が全て死亡していることを確認。
7. Aが中央chest4を操作。携行した鍵が通常ルールで消費され、施錠が解除される。1.6秒待って箱を開く。
8. 同じserver tickで、B→Aの順に同じ中央遺宝へloot要求を送る。Bだけが取得し、Aは品物なしとなる。両者とも箱から2.5m以内にいる。
9. e0の死体位置をCとする。Aは `(C.x+1,C.z)`、Bは `(C.x-1,C.z)` へ歩く。Aが死体を開いて1.6秒静止。
10. 同じserver tickで、A→Bの順に同じ死体遺宝へloot要求を送る。今回はAだけが取得する。
11. Aは `(C.x+0.65,C.z)`、Bは `(C.x-0.65,C.z)` へ近づく。到達許容0.2mを含む実測の両者間隔は約1.54m。正面を向き合い、防御せず、Aはidleごとに重攻撃、Bはidleごとに通常攻撃。2人とも実際にダメージを与え、Bが死亡する。
12. Bの鞄全体が通常のプレイヤー死体へ移ったこと、Bの鞄と倉庫が空であることを確認。Aがその死体を操作して1.6秒待ち、Bが先ほど取った中央遺宝を取り戻す。
13. Aは `(0,7.5)` → `(0,12)` → `(-12,12)`。最後の区間をz=12にすることで南西の柱を避ける。西出口は45秒で開き、このルートでは50.45秒に到着・操作する。
14. 帰還開始から3.95秒では生存中・倉庫0品を確認。さらに0.15秒進めると帰還済みになり、実測54.50秒で遠征終了。西出口の残り回数は2→1。
15. 保存JSONからサーバーを再起動し、A/Bが同じキーで再参加。Aの4品の倉庫、Bの死亡・空の鞄と倉庫を確認。以前の抽出操作の再送と、新しい連番での抽出再要求を両方送り、倉庫増殖・出口の二重消費がないことを確認する。

## 実測の戦闘・回復

時刻は遠征開始からの秒。テストの行動は状態条件で開始し、以下の時刻を無理に再現するためのワープや状態変更は行わない。

| 戦闘 | 交戦開始 | 重攻撃開始 | 撃破 | プレイヤーHP |
| --- | ---: | ---: | ---: | --- |
| A対南e3 | 8.10 | 9.45 | 10.30 | 110→78、11.30に薬で110 |
| B対北e2 | 15.85 | 17.25 | 18.10 | 110→62、19.10に薬で97 |
| A対中央e0 | 23.60 | 24.95 | 25.80 | 110→78 |
| A対中央e1 | 28.05 | 28.45 | 29.30 | 49→45 |

中央2体は連続して攻撃する。e0撃破後の回復待ちにe1から32ダメージを受け、26.80秒の薬で46→81、その回復後隙にさらに32を受けて49になる。e1との交戦中には盾で軽減した4ダメージを受ける。30.30秒に術を詠唱し、45→85へ回復する。

初期4番兵はこの向き・重攻撃の軌道では各1回の重攻撃で倒れた。固定ダメージ注入ではなく、通常の連続ブレードと頭部カプセルの判定による。人間の照準や別の間合いで同じ一撃撃破を保証するものではない。

PvP開始39.15秒: A=85 HP、B=97 HP。Aは39.15 / 41.00秒に重攻撃、Bは39.15 / 40.35 / 41.60秒に通常攻撃を開始。41.85秒にB死亡、Aは23 HPで生存。Aの対人被害は62、Bは通常の重攻撃2回を受ける。撃破数はA=4（AI3＋対人1）、B=1（AI1）。

回復合計:
- A: 薬2回（実回復32＋35）、灯守の術1回（40）。実回復107 HP、残り術4回。
- B: 薬1回（35）、術なし。残った薬1回は死亡時に死体へ移る。
- Aは23 HPで帰還し、初期片剣・初期盾・AI死体遺宝・中央箱遺宝の4品を倉庫へ保存。薬は消費済み、鍵は中央箱で消費済み。

ブラウザへ移す際は、中央で薬を飲む間にも敵が動くこと、盾を保持したままでも攻撃中は盾が下がることに注意。安全のために追加回復する場合も通常の薬・術だけを使い、元の未加工ルートと変更したプレイルートの結果を区別する。

## 実行と残件

`npx vitest run tests/unit/dungeon-raid-journey.test.ts --maxWorkers=1`

追加した試験のみで成功。型検査も成功。旧キャンペーンの長時間集約試験やブラウザを、この試験の成功に含めない。実際の2ブラウザで同じ参加→敵戦→loot競合→対人死亡→帰還→再読込を通すことが次の独立したゲート。

## ブラウザで変動する死体位置への経路（2026-10-08）

CI37724235694では中央番兵が追跡/退避により(-9.36,10.45)で死亡した。
四体撃破と箱競合は成功したが、上記の単体試験の固定死体位置を前提に直進する
ブラウザ操作は南壁で停止した。ブラウザでは四体撃破後、読み取り専用の壁/扉/生存相手の
位置から経由点を選び、通常キーで死体と西出口へ歩く。死体が壁/柱に近ければ
近くの空間へ対向する二人の足場をずらし、通常の相互作用距離と対人間隔を保持する。
生存体力、敵数、敵の強さ、競合/死亡/保存の検査、240秒条件は変更しない。
この修正の実ブラウザ受入は次の対象SHAで確認する。
