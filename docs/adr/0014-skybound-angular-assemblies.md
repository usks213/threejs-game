# ADR 0014: 創作部品の角運動、保存移行、休止

日付: 2026-10-04
状態: ローカル実装・自動試験済み。実機/公開多人負荷の確認は別ゲート。

## 決定

- DOM/Three.jsに依存しない `skybound/orientation.ts`, `rigid.ts`, `character.ts` を使用する。
- 接着グラフごとに質量中心と、箱の局所慣性＋平行軸項から3×3合成慣性を求める。
- 30Hz authority tickにつき固定2 substep、各構造物につき最大24接触、固定4 impulse反復。
- 角速度は4rad/s以下。長い構造物は回転による端部移動がsubstepあたり約0.1m以内となる追加の保守的上限を使う。
- 接触候補は各部品を横断して採り、先頭部品だけでmanifoldを使い切らない。最後に全体積のVoxel/人物/保護範囲検査を行う。
- 世界空間quaternion `q`、構造物COMの並進速度、世界空間 `angularVelocity` を保持する。`rotation` は互換用のyaw表現。
- 描画、選択outline、プレイヤーの部品衝突、搭乗座標、放射器方向も同じ姿勢を使う。
- 固定試練slabを含む接着体は角運動/並進をしない。元素反応による固定床破壊も禁止したまま。

## 保存と通信

- `skybound.version=2`。version1はyawからquaternion、角速度0、sleeping=falseへ移行する。未来版・非有限/非単位quaternion・上限外角速度は拒否する。
- 設計帳は各部品の姿勢を保持する。再建時の衝突/予算/原子的素材消費は継続。
- participant exportはq/角速度/sleeping/creator/sharedを型付き投影し、他者の個人在庫や設計を追加しない。
- 旧クライアントは新保存を読めないため、公開時にprotocol/build互換ゲートを更新する必要がある。
- recall履歴はposition/q/速度だけ。電力、耐久、環境状態、inventory、health、試練証拠を戻さない。4秒の両端を含め最大121サンプル/部品。

## Sleep / wake

- 支持され、線速度/角速度が小さい状態が60tick続くと物理を休止する。
- 全参加者から48m超の、搭乗者のない構造物は遠隔物理休止する。物体は削除しない。
- 接近、lease、搭乗、impulse、地形編集の影響域、近傍の有効な推進/水流でwakeする。
- 電池消費と燃焼/濡れ/融解などは休止と分離し、権威tickに従って進める。
- 休止中に同じposeを記録し続けず、古い履歴を期限で破棄する。
- SkyContext.terrainEditsの新規appendからwake範囲を得る。undoも対象編集の同じdirty領域を使用できる。

## 搭乗・復帰

- 2席以上はseat world transformで移動する。driverは既存の決定的選択を維持。
- 大きな転倒または頭上圧迫では操縦を停止し、各人の降車床を検査する。
- 床への退避ができなければ、車両上方または直近の近い安全位置で、頭上と他者/物体との非重複を検査して降ろす。上方退避には通常の落下が残る。
- 検査できる退避先がなければ壁を抜けてteleportせず操縦停止。既存の「帰還」も利用できる。
- 降車後の `sky-upright` はleaseを必要とし、36姿勢で障害/保護範囲を検査する。空間が足りなければ先に部品を持ち上げる。

## 既知の制約

- 構造物間には下記の保守的な接触伝達を追加した。各構造物の位置積分は引き続き順次処理し、相手の現在位置を静的境界として検査するため、世界全体の運動量保存solverではない。
- 車輪は箱形状の接地/操舵と下記の電動traction補助。独立した車軸、回転ジョイント、サスペンションは未実装。
- 浮力は第6区切りで各部品の姿勢付き9点の水没率・材質係数・質量から合力/合トルクを求める方式へ変更。混合材質でrootの順番が変わっても同じ浮力になる。ゲーム用係数であり、厳密な浸水体積積分/圧力分布・排水との双方向連成ではない。
- 接触は固定数のサンプルと全体積拒否による保守的手法。一般的な凸形GJK/EPAや完全な連続衝突検出ではない。
- 遠隔休止中の位置は積分しないため、遠方での軌道を後から再演算しない。
- 本機能で既存SphereBodyの岩個数に制限は追加していない。SkyPartの既存64枠/接着体16部品予算を維持する。

## 検証

- 保存version1移行/破損拒否、質量・慣性依存impulse、quaternion積分/recall、2席転倒退避と姿勢復帰、固定試練保持、sleep/wake、温度条件をunitで検査。
- 合成平面、150tick、定期impulseで1/4/16構造物・合計16/32/64部品を測定。2026-10-05の単一worker実行で、16構造物/64部品のNode p95は乾燥9.64ms、水10.91ms、最大14.90ms/14.60ms。snapshot約37–38KB、最大履歴7744フレーム。
- これは物理部分のNode測定であり、実地形cache、ネットシリアライズ、GPU、モバイルFPS、実接続人数保証を含まない。


## 保守的な構造物間接触（2026-10-05）

- `assembly-contacts.ts` の `transferAssemblyContacts` をrecall更新後、通常の各構造物積分前に1tick一度実行する。姿勢・位置・接着・所有者・inventory・電力・保存形式は変更しない。
- 部品IDで群と部品を整列し、swept AABBと15軸OBB SATで候補を絞る。並進のみ最大1/30秒先までsweepする。1部品対につき近似接触点1点、1構造物24接触、4反復。64部品では部品対は最大2016、接触対は最大768。
- COM速度と接触点の角速度から、反発なしの等大逆向きnormal impulseを求める。各群の合成慣性を使い、速度上限に当たる場合は両側のimpulse全体を同率で縮める。入力が通常上限内なら線速12m/s・角速4rad/sを超えない。既に上限を超える許容入力は独立clampで運動量を消さず、その入力速度より増加させない。
- lease・recall・牽引・乗員あり・全actorから48m超の群はcallerで除外。固定・凍結・試練・貸出部品はmodule側でも除外。休止中の自由物体は実際のimpulseで起こす。
- 全対象部品のcreatorが同一、または全対象部品が明示的sharedの場合だけ伝達する。他人の私物・異なる所有者を含む未共有群には伝達しない。共有物を押して他人の私物を動かす迂回も禁止する。除外された相手は従来の静的境界として残る。
- `physics.dynamicContacts` はこのprepass専用の接触対数。従来の `physics.contacts` は各substepの静的接触数のまま。双方の固定予算を混同しない。

### 最終境界検査の修正

- `skyPartsOverlap` の15軸OBB SATを近傍部品ごとに一度実行し、格子点だけでは見逃す薄い/回転した箱同士の重なりを拒否する。面接触は許可し、重なり判定の許容誤差は1e-6m。
- terrain・occupied・protected・boundsの体積検査は、各軸の両端を必ず含む最大.125m間隔の点列へ変更。kindごとに点列をキャッシュする。以前の片側+.01m開始格子は反対側の表面を含まず、回転角のある隅が壁へ約1.26mm入る統合試験で問題を再現した。
- 静的接触の位置補正はdepthの平均から、各normal/depth制約への固定4反復の投影へ変更。平均補正では一番深い隅が地面内へ残り、厳密なguardによって車両の全速度が失われる場合があった。最終guardを弱めず既存の二人乗り車両移動試験を保持した。

### 検証と費用

以下のNode時間は構造物間接触の区切りで測定した値（同日後続の車輪駆動・連続actor検査追加前）。後続変更の実機性能を示すものではない。

- 単体: 同質量/異質量、斜め衝突、角運動、回転箱、薄い箱のsweep、離反/すれ違い、同時上限、入力不正、所有権、静的除外、ID順序、sleep wake。seed固定200組では接触impulse段階の線形/角運動量と非増加の運動エネルギーを確認する。
- 統合: `powers.step` を通した対象への移動伝達、地形/建物/保護域の境界、actor、lease/牽引/乗員/遠隔休止/recall、他人私物と共有物による迂回、保存対象の無関係なフィールドの維持を確認する。
- 密集した64箱のprepass単独: warmup10tick後150tick、Node p50 2.02ms、p95 3.01ms、最大12.91ms。観測接触455対。これは完全なauthority stepの時間ではない。
- 密接する64自由箱のauthority step: 合成平面、150tick、交互方向の定期impulse。Node p50 13.16ms、p95 17.93ms、最大22.96ms。最大静的接触320、動的接触32対、履歴7744、snapshot37,518B。最終64箱の非重複と全tickの有限値を確認した。
- これらは単一workerのNode測定。実地形cache、ネットserialization、GPU、モバイルFPS、実人数/NAT条件を含まない。実機/公開多数接続は未検証のまま。

### 残る制約

接触伝達段階だけで運動量を保存する。後段の順次位置積分・地形応答・速度制限・drag・最終体積拒否は運動量を失いうる。回転sweep、厳密なface clipping、多点manifold、構造物間friction/反発、安定した積み重ね、押し合いの完全連成は実装していない。地形側は有限格子と最終姿勢検査であり、任意に薄い形状を含む一般的な連続衝突検出ではない。


## 接地車輪の駆動補助と連続actor境界（2026-10-05）

- `wheel-traction.ts` はsupport・drive wrench・rolling方向の純粋helperを提供する。姿勢/位置/所有者/電池を直接変更しない。1群16部品まで、車輪につき姿勢付きtread probe最大5点、下方.06m以内、上向きnormalと車輪upのy成分が.65以上の場合だけ接地とする。
- `SkyContext.solid` は地形とVoxel建物/樹木を含むため、これだけを支持面に使用する。`occupied` は動くSphereBodyの岩なので支持面にはせず、protectedと同じく接地候補の拒否条件にする。動く他の構造物/actor/水そのものから推進反力を得ない。
- wheelは個別toggleと接続switchの対象。driverがいて移動入力があり、ONの車輪が接地し、接続電池から給電できる場合だけ駆動する。consumerは1輪あたり2energy/s。空中・OFF・入力なし・driver離脱では車輪の駆動電力を使わない。エネルギー不足時は既存の原子的な給電判定を維持する。
- 前進/後退の目標速は6m/s。接触点の速度誤差に応じたforceを、1輪45および推定支持荷重×.65の小さい方で制限する。接地輪間で荷重を等分し、接触点から合力/COM周りトルクを求めてauthorityがdt積分する。操舵後は支持点と向きを取得し直す。
- uprightなwheelの支持接触では縦方向のrolling resistance .02、横方向の摩擦 .5を使う。他の面/転倒状態/他kindは従来の箱摩擦を維持。これはゲーム用の接地駆動補助であり、車軸の回転、独立サスペンション、実タイヤの摩擦/荷重移動を表すsolverではない。
- 車輪試験はforward/reverse、目標速度とforce制限、坂/姿勢/壁/空中、power/driver/input条件、ロード共有/重複支持/非有限値、読み取り予算、個別ON/OFFとswitchを含む。実際の `powers.step` で推進器のない二人乗り車を動かし、乗員間距離・電池差分・停止条件・障害物を確認する。既存の推進器による二人乗り車両試験も維持した。

### actor境界の追加修正

駆動した傾き付きslabがactorの半径.3mへ約1.24mm入る例を、旧.25m間隔の7点検査で再現した。`skyPartOverlapsCapsule` はworldで直立するcapsuleの中心segmentをbox局所座標へ移し、最大6面交差による8個以下の区切り・7区間以下で、区分二次の距離を最小化する。有限の固定費用でsegment-to-OBBを判定し、面接触のみ許可、非有限/不正な形状は重なりとして拒否する。authorityの部品移動ではradius .3m / height1.7mを明示し、自分の搭乗群のriderだけを除外する。歩行motor本体の1.45mより保守的な安全域であり、その高さは変更していない。

この区切りで型検査と関連50試験が合格。静的壁・連続capsule距離・電池・二人乗り・旧車両・接触・拠点の回帰を含む。新しい車輪の実機操作感、回線越しの多数接続、車軸/サスペンションは未検証または未実装のまま。

### 接する床の許容誤差

全境界検査の導入後、0.25mグリッドへ丸めた箱が床とちょうど接する作成を拒否する回帰を検出した。world.solidはdensity<=0なので、境界probeは各面から1µmだけ内側に置く。旧10mmオフセットには戻さず、約1mmの壁/人物侵入を拒否する厳格な統合試験を維持する。OBB同士とcapsuleの接触許容は別の厳密距離判定を使う。
