# ADR 0007 — 協力プレイのIDと専用サーバー保存

2026-10-04。8クライアントの複合操作で確認した問題を修正する。

- 建築、召喚した敵、飛び道具のIDは共通GameSimulationで一意に採番する。プレイヤーごとのAdventureで採番すると同時建築で衝突する。
- 地形操作のクールダウンはプレイヤーごとに管理する。一人の操作で別の人の操作を拒否しない。
- 敵の標的、近傍物理、資源生成は実参加者の位置を使う。Dedicated内部の仮ホストを標的にしない。ゲストにも水流と凍結面を適用する。
- Dedicatedの参加者はブラウザが生成する256 bitのランダムなcapabilityを持つ。同じオリジンのサーバーについてlocalStorageへ保存し、接続時だけ渡す。サーバーはSHA-256ハッシュを公開ID・保存IDに使う。capabilityをセーブ・スナップショット・ログへ含めない。同時に同じIDを使う接続は拒否する。旧クライアントは従来の一時sessionIdを使える。
- サイトデータを消した端末や別端末に自動で本人確認する仕組みではない。アカウント間同期は未実装。
- Dedicatedの保存は一時ファイルを書いてからrenameする。書込エラーが次回保存を永久に止めないようキューを回復し、失敗は接続者に通知する。同一Nodeプロセスで同じ保存先を持つ部屋は一つだけ。複数プロセスの共有ストレージは対象外。
- 敵の攻撃待ち時間が最終tickで負になると旧版は自分のセーブを拒否していた。更新時に0へ丸め、旧セーブの1tick以内の負値だけを読込時に修復する。

検証は8実Colyseus接続、128物体、水、全員のクラフト/攻撃/建築/地形操作/移動、再参加、保存データ再検証。計測はAuthorityの全プレイヤー処理を含む。ブラウザGPUや通信シリアライズはこのtick計測に含めない。CI artifactのsimulation-benchmarksへ33.3ms目標との比較を残す。Node計測をAndroid実機FPSとして扱わない。
