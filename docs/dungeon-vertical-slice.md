# 灰の回廊: G1/G2進行記録

基準: PR4-DUNGEON-1.0 / DAD EA S10 HF127 / 2026-10-06。原作同一や全110項目完了を意味しない。

## 分離と権威

`?mode=dungeon` が新しい独自PvPvE試作。通常の七つの灯キャンペーン、保存キー、既存協力部屋にはアクセスしない。新モードの画面から旧モードへ戻れる。mainへのマージなし。

既存PR4 Workerの既存CampaignRoom binding/classを再利用し、`/dungeon-room/<room>` を `dungeon-v1:<room>` へ分離。新しいDurable Object class、binding、migration、有料サービス、アカウント権限は追加しない。新モードの健康状態は `/dungeon-room/health`。旧relayは引き続きbrowser-hostと明記する。

新モードは20Hzのサーバールール。ブラウザは入力と操作意図だけを送り、位置・HP・命中・戦利品・抽出はサーバーが決める。秘密の再接続キーは部屋招待URLに含めない。UUID相当のランダムな非公開能力キーであり、外部アカウント認証や署名sessionの完成ではない。

保存の成功前に確定通知を送らない。保存不調では通信を安全停止。未知/壊れた保存から新しい倉庫を作って上書きしない。死亡/抽出/略奪/入場は永続checkpointに含める。通常の移動checkpointは最大2秒周期。サーバー再起動では経過時間を最大raid寿命まで進め、切断を戦闘回避にしない。

## 今回の限定範囲

- 最大6人の招待部屋。初期6職、1種類の独自32mダンジョン。
- 実際のSDF表面、共有武器軌道、壁遮蔽、近接PvP/PvE、盾、弓、有限回数の術。
- 10×5の鞄。箱/死体の排他的移転、4秒の帰還、死亡時の携行品喪失。
- 倉庫は部屋・探索者別10×10。別部屋を跨ぐアカウント倉庫/共有倉庫/市場ではない。
- 初期補給は空の鞄にのみ無償で支給する独自ルール。原作の経済数値ではない。
- 旧作の共通スタミナは持ち込まない。攻撃後隙/詠唱時間/術回数で制限する。

ジャンプ/四肢hurtbox/全perk/全職/深層/復活/商人/市場/ランク/音声/全コンテンツは本checkpointで完成扱いしない。各110-ID台帳に残件を保持する。公開規模の抗不正/接続スパム耐性/資源上限/バックアップ運用は未検証。

## 検証

初期ローカル重点20試験は通過。その後、実際の2 TCP/WebSocket接続・HTTP境界・クライアント入力/再接続も追加検証。型検査とViteビルドは通過。サーバー所有の命中、予兆、壁、同時lootの一勝者、100回再送、死亡喪失、抽出一回、再接続、保存失敗、壊れた保存を検証した。テストは直接ルールとモックポートによるもの。独立ブラウザ・現物WebSocket・実機の合格証拠ではない。

次の受入は独立2ブラウザの参加→敵/対人戦闘→loot競合→死亡/帰還→再読込による倉庫一回確認。公開SHA、Worker経路、UI、PC/タッチを別々に確認する。実機FPS/iPhone実機Safariを未測定のまま完了と報告しない。

## 公開前の回帰修正

独立監査で、北西/南東のspawn部屋が閉鎖されていた問題、下向き矢の速度を位置用スキーマで誤拒否する問題を発見。部屋の接続を修正し、両seedの全spawn→出口経路、全spawnの衝突、下向き発射checkpointからの再起動を追加試験。敵は初期spawnの索敵圏外に置く。

クライアントは視点yawを正規化し、入力25Hz上限、互換protocol拒否、二重タブ切替、破損した秘密キーの上書き防止を検証。

全単体集約は別途実行中。変更していない旧キャンペーンのsoakと寝台条件試験に、この共有環境でwall-time超過が出た。結果を隠したり閾値を緩めたりせず、集約終了後に失敗ケースだけを単独再検査する。

CIは変更パスを確認し、ダンジョン専用変更では旧長期経路を繰返さない。全型/単体/build、旧起動と保存分離、専用PC/Android二接続/帰還/再接続、WebKit起動/tap検査を保持。共通エンジン/保存の変更、main、手動実行、比較基点不明時は旧matrixを維持。過去の失敗を新たな成功として扱わない。

独立監査の再検査: 両seedの全6spawn→全出口、敵spawn衝突、下向き矢の保存復旧、falsy破損保存拒否を確認。追加1,500ランダムtickと同時抽出/死亡/次raidで所有品IDの重複なし。これは純ルールの検証で、実ブラウザや本番Workerの検証ではない。

集約結果（公開前）: 1354件中1351成功、旧soak/寝台条件のwall-time超過2件と新dungeon specのrouting未登録1件。routingを独立CIジョブ登録として修正し、PC/Android/WebKitの実行先を確認する新しい契約試験を追加、routing+scopeの11試験成功。旧2ファイルのみを1 workerで再実行し12試験成功（元の120秒/15秒制限は維持）。全体を重複実行せず、変更した新モードの重点試験と型/buildを最終確認し、公開CIの全単体結果を別途追跡する。
