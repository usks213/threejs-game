# PR #3: 地形の背景処理とスマホUI

## ユーザーが指摘したブロッカー

- 動作が重く、まともに遊べない。
- 地形生成/ロードが操作やゲーム進行を止める。
- スマホの複数の操作ボタンが重なる。

前のCI成功は、この実機での不具合を解決した証拠ではない。

## 原因と変更

### 背景処理

以前もWorkerはあったが、ゲームの30Hzシミュレーションと `meshBrick` が同じスレッドで動いていた。8msで処理ループを区切っても、1個のメッシュ生成が長い場合は中断できず、入力/物理を止める。

今回はシミュレーションとは別の専用Terrain Workerを1本追加。モバイルでワーカーを無制限に増やさず、1ジョブずつ距離/編集優先で処理する。地形の差分だけを増分で同期し、各ジョブのepoch/versionを照合。編集、範囲外への移動、再ロードで古い結果を使わない。新規ワールド読み込み時は旧子Workerを停止する。

Worker間はfine/coarse/grassのTypedArrayを転送し、複製しない。相対座標化、境界球、草の配置点生成も背景側で済ませる。ゲーム側のメッセージ受信では描画メッシュを作らずキューへ入れる。実際に描画するフレームにだけ最大2チャンク、512KiB、soft 2msで適用し、描画へ送信した後にクレジットを返し、未消費4メッシュで生成側へバックプレッシャーを掛ける。メニューで描画しない間にGPUアップロードを溜めない。描画していない空チャンクの削除はキューに積まず、実際の削除はアップロードとは別の個数上限で処理する。1つの不可分なアップロードが2msを超える可能性は残るため、hardなフレーム時間保証とは呼ばない。

描画/物理のVoxel寸法やHDR機能は削除しない。GPU-driven化したという主張はせず、今回の経路はCPUのマルチスレッド化。Voxel照準/遮蔽は固定間隔の全距離走査から境界判定付きDDAへ替える。

### UI

以前のGrid指定に、古い `position:absolute` が各ボタンへ残り、Gridの配置が効いていなかった。縦持ちを横画面へ回転しているのに物理画面のmedia queryを使う箇所もあった。

配置を一本化する。左は移動/走行、右は2列×3段の操作Grid、中央下は8クイックスロット。狭い横画面ではクイックスロットを4列×2段にし、照準操作/解体をその上へ置く。建築操作は別の中央上部Grid。ダイアログ中は背後のゲーム操作を隠す。Safe Areaと論理Viewportのcontainer queryを使用し、48px以上のタップ対象を維持する。

## 比較測定

`node scripts/benchmark-terrain-streaming.mjs 64`

同じgenerator-3、0.5m、64ブリック、118,943三角形。4ブリックのウォームアップ後に実GameSimulation.stepを30Hzで回す。Worker起動と初期化は測定外。水/物体を空にして地形メッシュの競合を分離する。

2026-10-04の再現測定（Node v24.19.0 / AMD EPYC）:

- 最大シミュレーションTick間隔: 59.13 → 34.16ms
- p95 Tick間隔: 56.38 → 33.79ms
- 最大イベントループ遅延: 32.76 → 3.02ms
- 同一メッシュの処理時間: 1432.40 → 1270.43ms

機械可読結果: `docs/benchmarks/terrain-streaming-2026-10-04.json`。
これはクラウドCPUの合成比較であり、スマホFPS/GPU時間/全ゲームの品質証明ではない。実機でまだ重い場合はフレーム/GPUコストを測って次のボトルネックを切り分ける。

## 確認

- epoch/version、編集中の古い完了、チャンク再読込、pause/resume、バックプレッシャー、全バッファ転送、処理中のsave/inputを単体/Worker境界テスト。
- main適用キューの個数/バイト/時間予算、置換/削除/リセットを単体テスト。
- 568×320 / 667×375 / 844×390 / 縦390×844の14状態（通常、照準、ハンマー、建築、地形、持物、制作、建築一覧、世界、取引、箱、設定、性能表示、協力）とSafe Areaのボタン/入力/summaryの矩形とタップ中心のヒット先を総当たり検査。スクロール後も確認し、スクリーンショットをCI成果物へ残す。
- 新ブラウザ検証は公開CIで実行。ローカルChromiumのsocket制限、クラウドブラウザのWebGL不可は検証合格に数えない。
- Android/iPhone実機のFPS・操作感は未検証。mainへはユーザーのプレイOK後に反映する。

最終ローカル確認: TypeScript成功、単体200件/34ファイル成功、productionビルド成功。ビルドに独立したterrain-workerアセットを確認。ブラウザのレイアウト/実操作はこの変更のCI結果が出るまで未確認として扱う。
